# Временное ТЗ: цифровая визитка

> Рабочий документ на время разработки. Перед завершением проекта удалить этот файл.

Создайте цифровую визитку — backend-приложение, которое презентует Вас как специалиста, с обязательным использованием:

- Git;
- TypeScript;
- Node.js;
- NestJS;
- Prisma;
- GraphQL;
- Docker.

Приложение должно предоставлять Apollo Sandbox (GraphQL Playground), через которое можно получить информацию о Вас, Вашем опыте работы, навыках и проектах.

## Данные

1. **Профиль:** имя, краткое описание, ссылки на GitHub/LinkedIn или другие профессиональные ресурсы.
2. **Навыки:** список навыков.
3. **Опыт работы:** компания, должность, период работы, достижения.
4. **Проекты:** название и ссылка на проект или репозиторий.

При запуске приложения база данных должна быть автоматически подготовлена и заполнена Вашими данными.

## GraphQL API

API должно позволять получить профиль и связанные с ним данные. Пример:

```graphql
query {
  profile {
    name
    description
    skills {
      name
    }
    experience {
      company
      position
    }
    projects {
      name
    }
  }
}
```

Конкретную структуру GraphQL API, базы данных и архитектуру приложения можно выбрать самостоятельно. Архитектурные решения нужно обосновать в `README.md`.

Бизнес-логика, работа с данными и GraphQL API должны иметь разумное разделение ответственности.

## Критерии оценки

В первую очередь оценивается качество инженерных решений, а не количество кода. Особое внимание уделяется:

- структуре приложения и разделению ответственности;
- работе GraphQL с вложенными данными и оптимизации запросов к базе данных;
- взаимодействию с базой данных;
- инициализации и заполнению базы данных;
- читаемости и поддерживаемости кода;
- корректной работе приложения после запуска с нуля.
